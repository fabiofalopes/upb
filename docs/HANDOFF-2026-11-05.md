## 2 — The four bugs found in the gap (all fixed, all need committing)

### 2.1 The probe used the wrong wire dialect

`openai-codex` speaks the **Responses** API, which needs a *list-shaped*
`input` and `stream: true`. The probe sent a Chat Completions body and got
`400 Input must be a list` — which looks exactly like a broken model.

This reported your **working primary as broken** for most of the session.

Fixed in `tools/entitlement.py` (three dialects) with a regression test:
`cli/test_dialects.py` (4 tests, passing).

### 2.2 The gateway's issuer is not in any local trust store

Chain: leaf `modelos.ai.ulusofona.pt` → `GEANT TLS RSA 1` →
`HARICA TLS RSA Root CA 2021`. Neither macOS's keychain nor Python's
certifi carries HARICA, and the server sends an incomplete chain.

Fixed by building `~/.config/upb/certs/lusofona-chain.pem` (HARICA root +
GEANT intermediate, fetched from curl's `cacert.pem`) and setting
`ssl_ca_cert` on both provider entries. **Verification stays ON** — this is
a pinned trust anchor, not `ssl_verify: false`.

> [!note] Two files exist
> `geant-tls-rsa-1.pem` (the intermediate alone — does **not** verify, it
> needs the root). `lusofona-chain.pem` (root + intermediate — **this is
> the one wired into the config**). The first is a dead end; keep it only if
> you want the intermediate on its own.

### 2.3 The health gate stopped gating after a config migration

The config migrated from `custom_providers:` to the newer `providers:` block.
The gate only read the old one — so it silently stopped gating the provider
it had been pinning. Fixed: the gate now reads **both**, resolves keys by
base_url across both (the `providers:` entry carries no `api_key`; the
credential lives in the `custom_providers:` entry or the pool), and honours
`ssl_ca_cert` / `ssl_verify`.

### 2.4 A missing helper made the gate read an empty config

`health_gate.py` called `_load_yaml()` which was never defined in that file
(it lived in `providers.py`). `NameError` → the config silently parsed as
`{}` → no `ssl_ca_cert` → every probe failed with a confusing SSL error.
Defined now, with the same PyYAML-fallback-to-Hermes-venv logic as the
other tools.

> [!tip] The general lesson
> Every tool in `tools/` parses YAML with a fallback to the Hermes venv,
> because **the system `python3` on macOS has no PyYAML**. And every YAML
> read now raises on parse failure instead of swallowing it — a swallowed
> exception turned "the config is broken" into "nothing is configured",
> which cost an hour of debugging this session.

## 4 — Known gaps in the tooling (fix before trusting it fully)

### 4.1 The gate cannot discover NEW upstream models

`discover_models: false` pins the picker to the declared list. So when the
gateway rotated to `lfm2-*` / `lfm3-*`, those models **cannot appear** — the
picker will never offer them, and `--apply` would empty the provider
entirely (correct per its rule, but it would hide a working provider).

**The missing feature:** compare the pinned list against live `/v1/models`
and *propose* additions, so the gate can say "the gateway now serves
`lfm3-1.7b` — add it?" rather than silently dropping the provider.

That is the single most valuable next feature. It is also the thing that
would have turned today's confusion into a one-line answer.

### 4.2 The fallback chain masked the primary failure

The Lusófona provider answered `STILL_OK` in a live Hermes test — **via the
fallback to `zai`**, not via the gateway. Nothing in the output said so.

**Options:** (a) make the pre-flight check each provider *without* the
fallback chain — it already does, which is why it caught this; (b) surface
"answered via fallback" in the session footer so a degraded primary is
visible. (b) is a Hermes-side change.

### 4.3 `upb` CLI is still not deployed

`~/bin/upb` is still the Aug 21 build. The repo version has
`registry build|show|validate|slots|resolve|drift` and `snapshot`.

### 4.4 The upb router is still not running

Proven working on this Mac on Oct 23 (OpenAI dialect → `ROUTER_OK`,
Anthropic dialect → `ANTHROPIC_OK`, Hermes through it → `HERMES_OK`).
Two blockers: no `routes.yaml` → `providers.yaml` converter, and no launchd
agent. Until this lands, `upb`'s `/usage` — the one metric source you own
that ties routing to cost — stays dark.

## 6 — Traps, so the next session does not re-learn them

- **The system `python3` (3.9) has no PyYAML.** Use the Hermes venv
  (`~/.hermes/hermes-agent/venv/bin/python3`) or the tools' built-in
  fallback. `yaml` also does not exist in the venv used by `execute_code`
  at some paths — check before assuming.
- **`upb verify --probe` makes real billable calls.** So does
  `tools/entitlement.py`. Both are 1-token but they are not free.
- **The `providers:` block carries no `api_key`.** The credential lives in
  `custom_providers:` or the credential pool for the same base_url. Resolve
  by base_url, normalising a trailing `/v1`.
- **`excluded_providers` is empty** — the gate has never run `--apply`.
- **Hermes's `/v1/models` on a credential-scoped key may differ from the
  provider's public catalogue.** The Lusófona key sees 5 models; that is
  what that credential can use, not what the gateway advertises.
- **The gate's `busy` bucket (429) keeps models selectable.** A
  rate-limited model is usually fine; excluding it would be wrong.
- **A retired model names its own replacement** in the error body
  (`"was retired on September 25, 2026. Try gemma4:31b-cloud"`). That is the
  clearest churn signal available — do not discard it.

## 7 — The standing rule

> [!important]
> **Nothing in this setup should be discovered by failing.**
>
> Right now it is: 13 days of silence, and the drift was found by trying to
> use things. The gate exists to invert that — probe on a schedule, offer
> only what works, and turn a retirement or an expiry into a notification.
>
> The three things that make it true:
> 1. **Schedule the scan** (`hermes cron create`, weekly) — without this the
>    gate is a tool nobody runs.
> 2. **Teach the gate to discover** (§4.1) — so a catalogue rotation becomes
>    "add `lfm3-1.7b`" instead of "the provider is gone".
> 3. **Spread the blast radius** (§3.2, §3.4) — one provider should not
>    carry 8 auxiliary tasks and 4 of 5 fallbacks.
